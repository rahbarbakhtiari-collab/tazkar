## ۱. هدف

این سند تهدیدها، کنترل‌های امنیتی، داده‌های شخصی، سیاست نگهداری و الزامات مخزن وردپرس را برای افزونه تذکار تعریف می‌کند.

اصل راهنما:

> داده را معتبر فرض نکن، دسترسی را بر اساس capability بررسی کن، nonce را جایگزین مجوز ندان، خروجی را در لحظه نمایش escape کن و داده شخصی غیرضروری جمع نکن.

## ۴. نقش و capability

به‌جای اتکا به نام role، capability بررسی می‌شود.

### capabilityهای پیشنهادی

```text
manage_tazkar
import_tazkar_items
review_tazkar_items
publish_tazkar_items
manage_tazkar_settings
view_tazkar_feedback
delete_tazkar_data
```

در MVP، همه capabilityها هنگام activation به Administrator اعطا می‌شوند.

### قواعد

- هر صفحه مدیریت `current_user_can()` را بررسی می‌کند.
- هر REST route مدیریتی `permission_callback` مشخص دارد.
- دسترسی به یک batch بر اساس capability و شناسه معتبر بررسی می‌شود.
- nonce تنها کنترل CSRF است و مجوز دسترسی نیست.
- عملیات حذف کامل داده capability جدا دارد.

## ۵. Nonce و CSRF

### الزامات

- فرم‌های مدیریت nonce اختصاصی دارند.
- عملیات AJAX/REST مدیریت از nonce وردپرس و cookie احراز هویت استفاده می‌کنند.
- nonce قبل از هر تغییر حالت بررسی می‌شود.
- GET برای عملیات مخرب استفاده نمی‌شود.
- لینک حذف یا rollback بدون تأیید POST/DELETE اجرا نمی‌شود.
- failure nonce با پیام عمومی و بدون افشای جزئیات مدیریت می‌شود.

### عملیات حساس

- آغاز import؛
- تأیید گروهی؛
- انتشار گروهی؛
- rollback؛
- حذف فایل؛
- تغییر تنظیمات؛
- حذف کامل داده.

## ۶. اعتبارسنجی، پاک‌سازی و Escape

### اصل

- validation برای رد داده نامعتبر؛
- sanitization برای پاک‌سازی داده مجاز؛
- escaping در آخرین لحظه و متناسب با context.

### نمونه نگاشت

| داده | اعتبارسنجی/پاک‌سازی | خروجی |
|---|---|---|
| enum | allowlist | `esc_html` |
| عدد | `absint` و range | `esc_html` |
| عنوان | `sanitize_text_field` با کنترل طول | `esc_html` |
| متن انگیزشی | متن ساده، کنترل جمله/طول | `esc_html` |
| URL | `esc_url_raw` | `esc_url` |
| textarea بازخورد | `sanitize_textarea_field` | `esc_html` |
| HTML مجاز | در MVP وجود ندارد | — |
| SQL | `$wpdb->prepare` | — |

متن عربی نباید با sanitizerهایی که نویسه یا اعراب را تغییر می‌دهند پردازش شود. برای آن:

- نوع داده رشته؛
- کنترل UTF-8؛
- کنترل طول؛
- ممنوعیت HTML؛
- ذخیره مقدار بدون تغییر معنایی؛
- escape با `esc_html()` هنگام نمایش.

## ۷. امنیت CSV و XLSX

### فایل‌های مجاز

- `.csv`
- `.xlsx`

فایل‌های زیر رد می‌شوند:

- `.xls`
- `.xlsm`
- `.ods` در MVP
- فایل بدون پسوند معتبر
- فایل با MIME و پسوند متعارض
- فایل رمزگذاری‌شده
- فایل دارای ماکرو

### محدودیت پیشنهادی

- اندازه پیش‌فرض: ۱۰MB؛
- حداکثر قابل تنظیم مدیر: ۲۵MB؛
- حداکثر ردیف MVP: ۵۰۰؛
- حداکثر ستون: ۶۰؛
- حداکثر طول سلول: بر اساس قرارداد داده.

### CSV Formula Injection

سلولی که با یکی از این نویسه‌ها آغاز شود:

```text
= + - @
```

به‌عنوان متن نگهداری می‌شود و هنگام export با روش امن escape می‌شود. افزونه هیچ فرمولی را اجرا نمی‌کند.

### XLSX

- فقط value سلول خوانده می‌شود؛
- فرمول برای تصمیم محتوایی پذیرفته نمی‌شود؛
- external link و object اجرا نمی‌شود؛
- archive قبل از پردازش از نظر تعداد entry و اندازه بازشده محدود می‌شود؛
- sheet انتخابی باید نام و تعداد ردیف معتبر داشته باشد.

### فایل موقت

- در پوشه uploads با نام تصادفی و دسترسی محدود؛
- URL عمومی مستقیم برای فایل خام نمایش داده نمی‌شود؛
- نام اصلی فقط به‌عنوان metadata پاک‌سازی‌شده ثبت می‌شود؛
- بعد از پایان دوره نگهداری حذف می‌شود.

## ۸. محدودیت منابع و DoS

- import به chunk تقسیم می‌شود؛
- memory_limit تغییر اجباری نمی‌کند؛
- timeout سرور با درخواست‌های کوتاه مدیریت می‌شود؛
- یک کاربر نمی‌تواند هم‌زمان چند import فعال اجرا کند؛
- endpoint تصادفی rate limit و cache دارد؛
- feedback محدودیت سرعت دارد؛
- queryها صفحه‌بندی و محدود هستند؛
- `ORDER BY RAND()` روی مجموعه بزرگ استفاده نمی‌شود.

## ۹. امنیت پایگاه داده

- نام جدول از ثابت افزونه و `$wpdb->prefix` ساخته می‌شود.
- مقدار کاربر در نام جدول یا ستون وارد نمی‌شود.
- queryهای پویا allowlist دارند.
- همه مقدارها با `$wpdb->prepare` یا APIهای وردپرس نوشته می‌شوند.
- indexهای لازم برای جلوگیری از query سنگین وجود دارد.
- schema migration نسخه‌دار است.
- خطای SQL به کاربر عمومی نمایش داده نمی‌شود.
- backup قبل از migration مخرب الزامی است.

## ۱۰. REST API

### عمومی خواندنی

- فقط `approved + publish`؛
- فیلدهای عمومی allowlist؛
- پارامترهای page، topic و per_page محدود؛
- schema مشخص؛
- cache header مناسب؛
- عدم نمایش meta داخلی.

### feedback

- فقط فیلدهای محدود؛
- nonce صفحه در صورت same-origin؛
- honeypot؛
- حداقل زمان تکمیل؛
- rate limit؛
- طول پیام محدود؛
- عدم پذیرش HTML؛
- پاسخ عمومی بدون اعلام جزئیات تشخیص spam.

### کاربر واردشده

- علاقه‌مندی فقط برای user فعلی؛
- user_id از body پذیرفته نمی‌شود؛
- از هویت نشست استخراج می‌شود؛
- حذف علاقه‌مندی نیز همان کنترل را دارد.

### مدیریتی

- permission callback غیرقابل حذف؛
- capability اختصاصی؛
- nonce REST؛
- validate_callback و sanitize_callback؛
- خطاهای استاندارد `WP_Error`.

## ۱۱. بازخورد و مقابله با هرزنامه

### داده‌های جمع‌آوری‌شده

- شناسه محتوا؛
- نوع بازخورد؛
- دسته گزارش؛
- پیام اختیاری؛
- user_id در صورت ورود؛
- زمان؛
- کلید rate-limit غیرقابل بازیابی.

### داده‌های جمع‌آوری‌نشده در MVP

- نام؛
- ایمیل؛
- شماره همراه؛
- موقعیت مکانی؛
- آدرس IP خام دائمی؛
- user-agent کامل؛
- fingerprint مرورگر.

### rate limit

- IP خام فقط در حافظه همان درخواست استفاده شود؛
- برای محدودسازی، HMAC کوتاه‌عمر با salt سایت ایجاد شود؛
- hash روزانه یا دوره‌ای قابل چرخش باشد؛
- پس از دوره rate-limit حذف شود.

## ۱۲. داده شخصی

### علاقه‌مندی مهمان

- فقط localStorage؛
- در سرور ذخیره نمی‌شود؛
- در سیاست حریم خصوصی توضیح داده می‌شود؛
- کاربر می‌تواند فهرست را پاک کند.

### علاقه‌مندی حساب‌دار

- `user_id` و `post_id`؛
- داده شخصی محسوب می‌شود؛
- در exporter وردپرس ارائه می‌شود؛
- در eraser حذف می‌شود.

### بازخورد

اگر به user_id متصل باشد، در exporter/eraser لحاظ می‌شود. بازخورد بی‌نام پس از حذف کاربر می‌تواند ناشناس باقی بماند، مشروط به حذف ارتباط قابل شناسایی.

### عملیات مدیر

auditهای امنیتی لازم می‌توانند user_id مدیر را برای پاسخ‌گویی نگه دارند؛ سیاست نگهداری آن روشن می‌شود.

## ۱۳. سیاست نگهداری پیشنهادی

| داده | دوره پیشنهادی |
|---|---|
| فایل خام import موفق | ۳۰ روز |
| فایل import خطادار | ۳۰ روز یا تا رفع خطا |
| گزارش ردیف import | ۹۰ روز پس از موفقیت |
| metadata بسته | تا زمان حذف محتوای مرتبط یا ۲۴ ماه |

| feedback باز | حداکثر ۲۴ ماه |
| rate-limit hash | حداکثر ۲۴ ساعت |
| علاقه‌مندی | تا حذف توسط کاربر یا حساب |
| log فنی debug | طبق تنظیم سرور؛ بدون داده اضافی |

دوره‌ها در تنظیمات حرفه‌ای آینده قابل تغییرند؛ MVP مقدارهای امن پیش‌فرض دارد.

## ۱۴. Privacy Exporter و Eraser

افزونه باید به ابزارهای داخلی وردپرس متصل شود.

### exporter

برای کاربر درخواستی:

- علاقه‌مندی‌ها؛
- بازخوردهای متصل؛
- تنظیمات شخصی آینده.

### eraser

- حذف علاقه‌مندی‌ها؛
- حذف یا ناشناس‌سازی بازخورد؛
- حذف تنظیمات کاربر؛
- عدم حذف محتوای عمومی که کاربر فقط آن را منتشر کرده، مگر سیاست مدیریتی جدا.

## ۱۸. امنیت نمایش و XSS

- همه داده متنی با `esc_html`؛
- attribute با `esc_attr`؛
- URL با `esc_url`؛
- JSON با توابع استاندارد؛
- inline JS تا حد امکان حذف؛
- داده PHP به JS با روش استاندارد وردپرس؛
- `innerHTML` برای داده کاربر استفاده نمی‌شود؛
- بازخورد در پنل به‌صورت متن ساده نمایش داده می‌شود.

افزونه سیاست CSP سراسری سایت را تغییر نمی‌دهد؛ ولی کد آن باید با CSP سخت‌گیرانه سازگار باشد.

- [ ] inputها validate و sanitize می‌شوند.
- [ ] outputها context-aware escape می‌شوند.
- [ ] SQLها prepare شده‌اند.
- [ ] CSV formula injection آزموده شده است.
- [ ] فایل XLSX مخرب و بزرگ آزموده شده است.
- [ ] فایل موقت پاک می‌شود.
- [ ] meta داخلی در API عمومی نیست.
- [ ] import نیمه‌تمام قابل ادامه یا rollback است.
- [ ] تغییر متن حساس وضعیت را بازمی‌گرداند.
- [ ] exporter و eraser کار می‌کنند.
- [ ] تماس خارجی ناخواسته وجود ندارد.
- [ ] فونت یا asset فاقد مجوز وجود ندارد.
- [ ] dependencyها اسکن شده‌اند.
- [ ] Plugin Check اجرا شده است.
- [ ] تست CSRF، XSS، SQLi و IDOR انجام شده است.
- [ ] پشتیبان و restore آزمایش شده است.

## ۲۷. معیارهای پذیرش امنیتی MVP

MVP قابل عرضه نیست اگر:

- عملیات مدیریتی بدون capability اجرا شود؛
- nonce تنها کنترل دسترسی باشد؛
- محتوای تأییدنشده از API عمومی قابل دریافت باشد؛
- HTML یا script از فایل ورودی اجرا شود؛
- فرمول CSV اجرا شود؛
- فایل خام برای عموم قابل دانلود باشد؛
- داده شخصی بدون export/erase ذخیره شود؛
- تماس خارجی بدون رضایت وجود داشته باشد؛
- کلید یا secret در کد وجود داشته باشد؛
- rollback خارج از batch هدف داده را حذف کند؛
- تغییر متن عربی بدون بازبینی ممکن باشد.

---

## ۲۸. تصمیم‌های امنیتی پیشنهادی برای تصویب

1. MVP هیچ تماس خارجی و هیچ کلید API نداشته باشد.
2. فایل‌های import حداکثر پیش‌فرض ۱۰MB و سقف تنظیمی ۲۵MB داشته باشند.
3. داده علاقه‌مندی حساب‌دار و بازخورد در exporter/eraser وردپرس قرار گیرند.
4. فایل خام import موفق پس از ۳۰ روز حذف شود.
5. feedback حل‌شده پس از ۱۲ ماه حذف یا ناشناس شود.
6. فونت و asset از CDN خارجی به‌صورت پیش‌فرض بارگذاری نشود.
