## ۱. هدف

این سند، معماری مصوب را به ترتیب اجرایی قابل توسعه تبدیل می‌کند.

هدف نخست، ساخت همه قابلیت‌ها نیست. هدف این است که کوچک‌ترین مسیر کامل و قابل آزمون ساخته شود:

```text
فعال‌سازی افزونه
      ↓
ثبت CPT و فیلدها
      ↓
خواندن فایل CSV
      ↓
اعتبارسنجی یک ردیف
      ↓
پیش‌نمایش
      ↓
ورود به‌صورت Draft
      ↓
نمایش صفحه عمومی
      ↓
بازگردانی همان بسته
```

تا زمانی که این مسیر پایدار نشده، قابلیت‌های فرعی مانند ایتا، پوستر تصویری، تحلیل پیشرفته و نسخه Pro وارد توسعه نمی‌شوند.

---

## ۲. اصول اجرای فنی

1. توسعه به‌صورت افزونه واحد و ماژولار انجام می‌شود.
2. هر Sprint باید یک خروجی قابل نصب و قابل آزمون داشته باشد.
3. migration، امنیت و rollback از ابتدا ساخته می‌شوند؛ نه پس از تکمیل رابط.
4. متن عربی در تمام مسیر با hash کنترل می‌شود.
5. هیچ محتوایی در import خودکار منتشر نمی‌شود.
6. CSV زودتر از XLSX پیاده‌سازی می‌شود.
7. رابط مدیریت ابتدا ساده و بومی وردپرس است.
8. JavaScript فقط برای پیشرفت import و تعامل ضروری استفاده می‌شود.
9. هر قابلیت پیش از توسعه، معیار پذیرش دارد.
10. تغییر قرارداد داده بدون migration و نسخه جدید ممنوع است.

---

## ۳. فازهای پیاده‌سازی

### فاز A — زیرساخت و Bootstrap

خروجی:

- بسته نصب‌شدنی افزونه؛
- بررسی نسخه PHP و WordPress؛
- autoload؛
- activation/deactivation؛
- capabilityها؛
- migration پایه؛
- تنظیم نسخه افزونه و schema.

معیار پایان:

- افزونه روی WordPress تمیز فعال و غیرفعال شود؛
- هیچ خطای PHP ایجاد نکند؛
- جدول‌های پایه فقط یک‌بار ساخته شوند؛
- غیرفعال‌سازی داده را حذف نکند.

### فاز B — مدل محتوا

خروجی:

- CPT `tazkar_item`؛
- taxonomyهای موضوع و برچسب؛
- ثبت metaهای قرارداد داده؛
- وضعیت محتوایی؛
- revision و hash متن عربی؛
- تغییر فیلد حساس → `needs_recheck`.

معیار پایان:

- یک محتوا از پنل ساخته و ذخیره شود؛
- meta در REST فقط طبق allowlist ظاهر شود؛
- تغییر عربی یا مأخذ وضعیت را بازگرداند.

### فاز C — هسته اعتبارسنجی

خروجی:

- Value Objectهای enum؛
- validator قرارداد ۱٫۱؛
- قواعد قرآن و حدیث؛
- محدودیت عنوان و تلنگر؛
- کدهای خطا؛
- تست واحد.

معیار پایان:

- نمونه‌های معتبر پذیرفته شوند؛
- نمونه‌های نامعتبر با کد دقیق رد شوند؛
- validator به WordPress وابستگی مستقیم نداشته باشد.

### فاز D — درون‌ریز CSV

خروجی:

- بارگذاری امن CSV؛
- کنترل header و schema؛
- پیش‌نمایش؛
- نتیجه ردیف‌محور؛
- ورود Draft؛
- ثبت batch و row؛
- جلوگیری از اجرای فرمول.

معیار پایان:

- فایل ۱۰ ردیفی نمونه وارد شود؛
- ردیف خطادار post ایجاد نکند؛
- قطع عملیات وضعیت نامشخص ایجاد نکند؛
- فایل تکراری هشدار دهد.

### فاز E — ورود مرحله‌ای و rollback

خروجی:

- import chunked؛
- cursor؛
- resume؛
- rollback بسته؛
- گزارش نتیجه.

معیار پایان:

- فایل ۱۵۰ ردیفی در چند درخواست پردازش شود؛
- اجرای مجدد post تکراری نسازد؛
- rollback فقط داده همان batch را به Trash ببرد.

### فاز F — XLSX

خروجی:

- OpenSpout پیشوندگذاری‌شده؛
- خواندن value سلول؛
- محدودیت فایل و archive؛
- خروجی برابر CSV.

معیار پایان:

- CSV و XLSX یکسان، نتیجه محتوایی یکسان بدهند؛
- فرمول و فایل نامعتبر اجرا نشوند؛
- تداخل namespace وجود نداشته باشد.

### فاز G — بازبینی و انتشار

خروجی:

- صف بررسی؛
- فیلتر confidence؛
- تأیید تکی؛
- نمونه‌برداری و تأیید گروهی؛
- جداسازی تأیید از انتشار.

معیار پایان:

- مورد `low` یا بحرانی گروهی تأیید نشود؛
- خطای بحرانی تأیید گروهی را متوقف کند؛
- تأیید، انتشار خودکار انجام ندهد.

### فاز H — Frontend

خروجی:

- صفحه تکی server-rendered؛
- آرشیو؛
- صفحه موضوع؛
- کارت اصلی؛
- یک مأخذ نمایشی؛
- related و random؛
- روشن و تیره.

معیار پایان:

- عرض ۳۲۰px بدون اسکرول افقی؛
- عربی، ترجمه و تلنگر بدون JavaScript دیده شوند؛
- CSS روی صفحات دیگر اثر نگذارد.

### فاز I — تعامل و حریم خصوصی

خروجی:

- share؛
- favorite مهمان؛
- favorite حساب‌دار؛
- feedback؛
- privacy exporter و eraser؛
- rate limit.

معیار پایان:

- مهمان بدون ارسال سروری favorite داشته باشد؛
- کاربر بتواند داده خود را export و erase کند؛
- تماس خارجی ناخواسته وجود نداشته باشد.

### فاز J — آماده‌سازی Release Candidate

خروجی:

- CI کامل؛
- Plugin Check؛
- readme.txt؛
- POT؛
- build reproducible؛
- upgrade و rollback rehearsal؛
- ZIP RC.

## ۴. ترتیب Sprintها

| Sprint | تمرکز | خروجی اصلی |
|---|---|---|
| Sprint 0 | محیط و اسکلت | افزونه نصب‌شدنی و CI پایه |
| Sprint 1 | مدل محتوا | CPT، taxonomy و meta |
| Sprint 2 | validator | قرارداد داده و تست‌ها |
| Sprint 3 | CSV preview | بارگذاری و گزارش ردیف |
| Sprint 4 | CSV import | Draft، batch و duplicate |
| Sprint 5 | resume/rollback | import مرحله‌ای و بازگشت |
| Sprint 6 | XLSX | OpenSpout و محدودیت امنیتی |
| Sprint 7 | review | صف و تأیید |
| Sprint 8 | frontend | کارت و صفحات عمومی |
| Sprint 9 | interaction/privacy | علاقه‌مندی و بازخورد |
| Sprint 10 | RC | آزمون، بسته و staging |

Sprint به معنی بازه زمانی ثابت نیست؛ هر Sprint یک بسته کاری با Definition of Done مشخص است.

## ۷. خروجی قابل نمایش Sprint صفر

در پایان Sprint صفر، صفحه‌ای در مدیریت با عنوان «تذکار» وجود دارد و فقط این اطلاعات را نشان می‌دهد:

- نسخه افزونه؛
- نسخه schema؛
- نسخه WordPress و PHP؛
- وضعیت جداول؛
- وضعیت نیازمندی‌ها؛
- پیوند به مستندات داخلی توسعه.

این صفحه هنوز ابزار import یا تولید محتوا ندارد.

| خطر | کنترل |
|---|---|
| معماری بیش از حد پیچیده | dependency injection ساده و بدون framework |
