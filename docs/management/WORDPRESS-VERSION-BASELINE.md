## ۳. وضعیت نسخه‌های پیش‌انتشار

در تاریخ بررسی، WordPress `7.1` در مرحله Beta قرار دارد. نسخه‌های Alpha، Beta و Release Candidate:

- برای Production پیشنهاد نمی‌شوند؛
- مقدار `Requires at least` پروژه را تعیین نمی‌کنند؛
- جایگزین آزمون روی آخرین نسخه پایدار نیستند؛
- فقط می‌توانند در آزمون آینده‌نگرانه جداگانه و غیرمسدودکننده استفاده شوند.

## ۴. قواعد پروژه

1. هیچ سند، Issue، PR، هدر افزونه یا workflow نباید به نسخه منتشرنشده به‌عنوان حداقل رسمی اشاره کند.
2. `Requires at least` و خط مبنای آزمون پروژه باید `7.0.2` باشند.
3. سازگاری با WordPress پایین‌تر از `7.0.2` هدف پروژه نیست.
4. کد جایگزین یا مصالحه امنیتی برای نسخه‌های پایین‌تر ساخته نمی‌شود.
5. آزمون روی نسخه پایدار جدیدتر فقط پس از انتشار رسمی انجام می‌شود.
6. افزایش حداقل پشتیبانی، یک تغییر اثرگذار است و باید پیش از کدنویسی به‌ترتیب در این موارد ثبت شود:
   - این سند؛
   - منشور و وضعیت پروژه؛
   - دفتر تصمیم یا یادداشت تطبیق؛
   - Issue و PR فعال؛
   - `readme.txt` و هدر افزونه؛
   - CI و آزمون‌های WordPress؛
   - گزارش Sprint و Changelog.

## ۵. اصلاح خطای ثبت‌شده
